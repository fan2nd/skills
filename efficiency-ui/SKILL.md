# 效率优先 UI 设计

先保证用户能迅速看懂当前状态、找到主操作并完成任务，再考虑装饰。默认浅色、紧凑、清晰；紧凑不是缩小文字或触控区域。明确要求、设备限制、可访问性与必要的安全提示优先。

## 先做这三件事

1. 查现有页面、组件、样式变量和目标屏幕。沿用成熟的设计系统；只改任务范围，不顺手换主题、框架或重做导航。无现成规范时用下方默认值。
2. 每个页面先定一句主任务，再排「标题与当前状态 → 主操作 → 任务内容 → 辅助信息」。首屏优先露出主操作和关键状态，避免横幅或说明把它们挤下去。每个任务区域只突出一个主按钮，次要和危险操作分开。
3. 优先做完整的操作路径，再细化样式。若只要求设计，交付布局、关键交互和状态，不自行改代码；若要求实现，复用真实组件、接好数据与事件，并完成下方自检；只审查时按影响排序列出具体问题和修法。

## 视觉硬规则

- **字号与尺寸统一。** 不为单个页面写随意数值。定义并复用语义字号、间距、圆角、颜色和组件尺寸；同类按钮和输入框对齐，同一规格贯穿产品。
- **层级靠对齐、间距和字重。** 首选平直布局与轻分隔。只在内容确实需要分组或独立交互时用卡片；不默认卡片套卡片，不使用渐变、玻璃效果、重阴影、大面积深色块或装饰动画。
- **浅色不等于低对比。** 用清楚的正文色，避免浅灰正文和仅凭颜色判断状态；焦点、错误和选中态必须可辨。普通文本对比度至少 4.5:1，大文本至少 3:1；关键控件边界、状态和焦点指示与相邻颜色以 3:1 为基线。
- **优先一个主要滚动区。** 文档、移动表单可正常整页纵向滚动；工作台可让表格或内容区承担主要滚动。禁止为凑一屏裁掉信息、缩小字体或叠加同轴滚动区。宽表确有需要时把横向滚动限定在表格内。窄屏先调整布局，再决定分页或滚动。
- **文案就地、够用。** 按钮用明确动作，字段用稳定名称和单位，错误说明问题与下一步。辅助说明放在可点击、可聚焦的帮助入口或按需展开；关键限制、风险提示和阻断原因留在操作处，不藏在悬浮提示里。不写重复标题、功能自夸或实现说明。

## 错误与失败提示

- **用模态弹窗，右下角放「确认」按钮。** 操作失败、提交校验被拒绝、连接或保存出错时，用弹窗说明发生了什么、必要时说明如何恢复；不以自动消失的 Toast、页内横幅或悬浮提示替代。保留用户输入。点击「确认」只关闭提示，不重试、不提交、不执行其他操作。
- **让用户能定位和修正。** 提交时有多个错误，只弹一次并指出要改哪些字段；关闭后聚焦首个需要修正的字段，无对应字段则恢复到触发控件。编辑时可用字段标记帮助定位，不随每次键入弹窗。复用统一弹窗组件，弹窗打开时键盘焦点留在弹窗内。

## 没有设计系统时的默认值

- Web/桌面：字号按辅助 12、正文 14、区标题 16、页标题 22 px；正文行高约 1.5，间距用 4/8/12/16/24/32 px。默认圆角 6 px；标准按钮和输入框同高 36 px。
- 移动和触屏：正文优先 16 逻辑像素，触控区域默认至少 44×44 逻辑像素，服从平台更高要求；嵌入式优先按物理屏幕、观看距离和输入方式验证，不机械套用 Web 像素值。小屏优先拆分任务或改布局，不靠压缩字号。
- 浅色起点：页面背景 #F6F7F9、表面 #FFFFFF、正文 #1F2937、辅助文字 #4B5563、主操作 #1D4ED8（配白字）、控件边界 #6B7280。装饰分隔可更轻，但不能代替关键控件轮廓。错误、成功、警告另用语义颜色，同时配文字或明确图标。

## 实现硬规则

- 复用现有按钮、输入、表格、弹窗和状态组件；没有时只抽取已经重复或明确会复用的模式，不先造一套组件库。保留键盘操作、可见焦点和可访问名称；不要用普通容器假扮按钮。
- 页面组织布局与状态，组件展示状态并发出用户意图，业务逻辑负责校验、执行和持久化。异步操作要处理加载、空、失败和成功；提交中防重复提交，失败尽量保存输入并给可用的恢复动作。
- 原始日志、异常栈、调试 JSON、设备报文和内部错误码不得直接渲染到业务组件。写入日志设施或专用诊断视图；业务界面只显示人能采取行动的状态和说明。用户明确需要日志页时，与日常工作界面分离。

## 交付前逐项检查

- 在目标尺寸和一个更窄的代表尺寸看实际界面，确认主操作、关键状态、单位和危险提示可见；检查长文本、缩放、溢出与滚动归属。
- 实际走一遍主流程与失败恢复；确认失败弹窗的「确认」按钮在右下角，关闭时不提交或重试；检查键盘/触控、焦点、对比度，以及同类组件是否使用相同规格。
- 检查界面不存在调试输出、无效控件、重复说明或未经要求的功能变化。能运行就用截图、模拟器或真机标记验证；不能运行就明确列出未验证项，不声称通过。
